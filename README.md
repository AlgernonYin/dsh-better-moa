# dsh-better-moa

Better MoA 为 DeepSeek Harness 提供可配置的参考模型面板。选择 `moa/<preset-id>` 后，参考模型提供无工具意见，聚合器继续宿主的 Agent loop 和工具调用。发行包不包含个人预设、渠道地址或凭据；新安装需自行配置聚合器和参考模型。

## 使用

在设置中的 Better MoA 页面新增预设，选择宿主模型目录里的 Provider / Model。编辑器当前选中的预设与通用设置里的默认预设互不联动。设置自动保存，模型目录自动同步；保存失败时保留草稿并显示错误。默认预设用于 `/moa` 与诊断，删除全部预设后默认项为空。

聚合器 reasoning effort 默认跟随会话模型选择框，也可选择固定档位。仅发送所选模型支持的 effort。参考模型可分别配置输出上限、上下文窗口、超时及持久化策略。

## 参考调用频率

| 频率 | 行为 |
|---|---|
| 每轮会话开始 `user_turn` | 每个用户回合开始咨询一次 |
| 每 N 轮工具迭代 `every_n:N` | N 为 1–999；N=1 即每次迭代，旧 `per_iteration` 自动迁移 |
| 智能参考调度 `smart` | 开始咨询一次；不足 minGap 不调用判断器，达到 maxGap 直接咨询，中间由判断器识别阶段完成或卡住 |
| 每轮会话开始和结束 `user_turn_end` | 开始咨询一次，准备结束时再做一次 QA；完整且明确的 REVISE 意见让聚合器在同一回合修改一轮 |

结束 QA 每回合最多一次，标记跨引擎重建保存。截断、未知判词、超时和调用失败均记为 unavailable，不作为 PASS。修改后的步骤可正常结束；Stop、clear 或配置切换会取消旧审阅。QA 总时限包含排队、状态保存与模型调用。

## 调用并行与批量注入

多条参考请求并行启动，同一持久参考槽跨运行使用互斥。每一轮参考结果等到全部完成、失败或达到截止时间后封存，并至多注入一次；迟到结果不再补发。预设的交付方式为：

- **等待参考**（`delivery: wait`）：主模型等待整批封存后继续。
- **后台参考**（`delivery: background`）：主模型继续执行，整批意见在后续正常进入的 pre-step 注入。没有后续步骤时不会主动唤醒已结束的 Agent。

旧逐参考 sync/async 配置仍可迁移，但不会把同一批意见拆成多次注入。参考超时会在统一意见卡中显示不可用原因。历史尚未提交时，同一份意见也不会重复返回；引擎重建后缺失的缓存意见最多恢复一次。

普通参考意见采用宿主历史替换机制，只保留最新一份活动意见；旧正文仍在审计事件中。结束 QA 原位追加，不替换开始时的意见。参考与 QA 卡可折叠；展示正文与模型实际收到的指导前言分开。

## 智能调度器

所有智能预设共享通用设置中的 scheduler。判断器可不选，此时使用开始咨询与 maxGap 兜底；其他频率不需要判断器。

可使用宿主小模型、兼容接口小模型、JEV、OpenAI Decisions 或 Luna Responses。兼容接口的协议、baseURL、模型、凭据环境变量及连接测试在设置中配置。凭据应通过环境变量提供，不写入公开预设或报告。失败、超时、拒答及不合法判断均按“暂不咨询”处理。

调度上下文默认 128000 字符，可配置 100000–512000。它选择早期背景、当前用户请求及近期记录；单条超长内容保留首尾并标明截断。字符数不是 token 数，也不代表判断准确率。

OpenAI 调度通道使用独立 HTTPS 传输及显式缓存，缓存账本受会话、接口、容量和布局隔离。失败或取消不提交旧断点；进程重启、TTL 过期及窗口变化仍可能重付前缀。JEV 未报告缓存计数时显示未知，不推算命中率。

## 上下文、输出上限与 billion-context

参考使用请求发出前的宿主历史投影，包含对话、工具调用和结果，排除 MoA 自己的意见以免反馈循环。每个参考按自己的窗口裁剪，尽量保留当前任务及近期证据；小窗口参考无法看到与大窗口聚合器完全相同的历史。单条消息和总转录仍受字符上限约束。

预算优先采用逐参考显式 contextWindow，再采用有效的已学习限制或模型目录；缺失时使用保守回退。输出预算和请求的 system、scaffold、source 均计入完整请求检查。对于 bili 明确报告“未转发”的窗口拒绝，学习有效上限并最多缩小重试一次；显式窗口也不能跳过本次拒绝限制。第二次失败或预算不能缩小时直接报告，不循环重试。预算使用估算和余量，不能替代供应商实际 tokenizer。

参考显式 maxTokens 原样传给模型适配器，空回复不会触发放大上限的重试。最终上游限制仍受渠道及中间件影响。尤其某些 bili 版本会恢复带工具主模型请求的输出预算，因此不能把聚合器 maxTokens 描述为跨中间件的绝对硬上限。

普通聚合器请求保留主会话归属；原生会话路由通过宿主 adapterStream 分派，避免嵌套调用改变 ACP 归属。缺少该接口时明确报错。参考和调度使用私有会话 id，不向其提供工具，也不伪造 bili bypass 标记。辅助参考缺少宿主窗口映射时，bili 可能回退到通用模型表；可按 bili 官方文档为已确认的渠道/模型声明真实窗口，勿盲目扩大全局窗口。

## 显式路由能力

聚合器与参考均可在 `presetOverrides` 的对应路由下配置 `capabilities`：

```yaml
capabilities:
  nativeSession: true
  requestReconciliation: true
  adviceBoundary: true
```

`nativeSession` 表示后端按 sessionId 保存会话；`requestReconciliation` 表示后端会核对完整请求并在历史改写后重建会话；`adviceBoundary` 启用请求内的固定意见缓存分隔符。后两项默认关闭，必须经渠道验证后显式开启。显式 false 优先于兼容检测。未声明时，仅对宿主 DeepSeek 原生供应商及含 claude-tui / session 的路由作保守的有状态识别，不推断其重写能力。设置编辑器会保留这些高级字段。

旧版本针对特定个人 Provider 名称的自动例外已移除；升级前应为依赖这些例外的路由补充能力声明。普通无状态接口无需声明。

兼容判断接口必须填写模型名。HTTPS 调度通道的环境代理支持依赖 Node 的 `proxyEnv` 功能；需要该功能时使用支持它的 Node 24 版本，Node 20 不提供等价保证。

## 缓存与原生会话

参考槽由主会话、预设、稳定参考 id、provider/model 和 cacheScope 隔离。普通追加尽量保持请求前缀；窗口按较大步长推进，减少频繁重建。sessionPolicy 可选择自动、稳定或轮换：

- 自动按路由特性选择；无上游会话状态的路由可以保留缓存亲和性。
- 稳定在允许的窗口重建中保留传输身份；仅适合无状态或能核对完整请求并重建历史的后端。
- 轮换在重建时更换传输身份，避免有状态后端继续使用旧上下文。

真实历史改写、清除、过期、渠道切换及缓存 TTL 仍可失效。稳定 session id 不保证缓存命中，也不能使不支持历史改写的原生后端自动支持该能力。参考内容、工具与 replay 完整性优先于缓存。

某些原生 TUI 渠道需要后端插件正确处理请求历史重写与缓存断点；安装本包不会自动安装或升级后端。应独立验证目标渠道的续接、压缩、历史替换和取消行为。

## 配置与诊断

| 配置 | 默认或含义 |
|---|---|
| presetOverrides / defaultPreset | 空用户预设表 / 空默认项 |
| scheduler | 共享判断配置，minGap 2、maxGap 12、threshold 0.6 |
| referenceTimeoutMs | 600000 ms；逐预设、逐参考可缩短，受整轮截止约束 |
| deadlineMs | 900000 ms；参考阶段总时限 |
| reviewTimeoutMs | 60000 ms；结束 QA 总时限 |
| maxDialogueChars / maxTranscriptChars | 4000000 字符 |
| maxMessageChars / maxAdviceChars | 24000 / 20000 字符 |
| persistentTags | `['*']`，逐参考可覆盖 |
| queueBudgetMs | 0；不另设槽锁等待时限，仍受取消和阶段截止约束 |

`moa_status` 显示运行版本、预设、加载函数哈希、客户端 revision 及近期调用诊断。`moa_status {"action":"sync-client"}` 请求宿主重建客户端资源，随后刷新现有 GUI 并核对实际版本。`/moa clear` 清除派生参考状态。

`moa_probe` 与 `/moa <preset> <prompt>` 会调用真实模型并产生费用。发行包不包含独立 benchmark、个人迁移脚本或历史测试凭据。

## 验证边界

0.9.0 运行时代码通过 313 项本地 Node 回归，包括独立窗口、完整 wire 预算、显式窗口拒绝后一次重试、输出上限、短请求实际 fit、批量超时、重复交付防护及结束 QA 生命周期。它们不等同于所有供应商的在线验收。

历史版本有受控任务、缓存与 QA 的真实调用证据，但不能据此保证任意任务质量提升、所有渠道的缓存命中率或自动采纳每条意见。聚合器被要求核对参考发现、处理冲突；参考意见不构成用户授权，也不能代替真实工具证据。
